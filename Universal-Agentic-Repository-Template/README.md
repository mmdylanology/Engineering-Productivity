# Universal Agentic Repository Template

> **A Production-Ready, Battle-Tested Engineering Blueprint for Human & AI-Agent Pair Programming**  
> *Maintained by Engineering Productivity | Usable across any backend, frontend, data, or AI repository.*

---

## Why This Exists

As software engineering teams transition to AI-assisted development (Claude Code, Cursor, Antigravity, Windsurf, local LLMs), traditional repository setups break down:
1. **Context Bloat:** Massive instruction files consume 80% of token budgets, causing LLMs to ignore instructions.
2. **Documentation Rot:** Human-written docs drift from code; AI agents generate broken code based on stale READMEs.
3. **Hallucinated Joins & Metrics:** LLMs generate ad-hoc SQL that invents non-existent columns and invalid joins.
4. **Git Churn:** Storing runtime analytical data in Git creates massive merge conflicts and review fatigue.
5. **Rogue AI Edits:** AI assistants accidentally delete architectural decisions, bypass security checks, or hardcode magic numbers.

This repository provides the **universal solution** to these problems. It is designed to be copied, customized, and dropped into **any project or repository**.

## The Core Architectural Law: The Three Planes

```
+--------------------------------------------------------------------------------+
|                         PLANE 1: INTENT (Git, Reviewed)                        |
|  Source Code | params.yaml | Semantic Contracts | Curated Knowledge (OKF)      |
|  ADRs & QDRs | Agent Rules & Skills | Runbooks | Pipeline Definitions | Tests  |
|  Property: Small, human-reviewed, diffable, slow-changing, authoritative       |
+---------------------------------------+----------------------------------------+
                                        | compiled by CI & Pipelines
                                        v
+--------------------------------------------------------------------------------+
|                 PLANE 2: OBSERVATIONS (Lakehouse & DBs, Append-Mostly)         |
|  Raw API pulls | Parsed documents | Analytical tables | Run receipts           |
|  Embeddings | Graph node/edge tables | Session transcripts | Audit logs        |
|  Property: Large, machine-written, reproducible from Plane 1 + sources         |
+---------------------------------------+----------------------------------------+
                                        | indexed & projected
                                        v
+--------------------------------------------------------------------------------+
|              PLANE 3: INDEX & SERVING (MCP, Catalogs, Generated Views)         |
|  Data catalog | MCP servers | Generated schema projections                     |
|  Static HTML graph explorers | Metric catalogs | Doc sites                     |
|  Property: 100% generated, disposable, never hand-edited                       |
+--------------------------------------------------------------------------------+
```

> **The Golden Law:**  
> *Git holds intent. The lakehouse holds observations. Catalogs hold the index. Agents hold nothing they cannot re-derive.*

## The 6 Universal Pillars Included in This Template

| Pillar | Location | Purpose & Tools |
| :--- | :--- | :--- |
| **1. Knowledge-as-Code & Semantic Layer** | `semantic/`, `knowledge/` | Defines metrics and entities as YAML. Compiles prompt intent into deterministic SQL. Implements Google OKF v0.2 Attested Computations. |
| **2. Agent Rules & Context Hierarchy** | `AGENTS.md`, `.agents/rules/`, `.agents/skills/` | Tier 1 (Root), Tier 2 (Scoped rules), and Tier 3 (On-demand Agent Skills via agentskills.io). Automated adapters via `tools/agentsync.py`. |
| **3. Agent Memory & Task State** | `.beads/`, `.agents/sessions/` | Git-native task graph (`bd` CLI) and reviewable session handoff notes. No external SaaS tracker required. |
| **4. Knowledge Graphs & Visual Topologies** | `tools/viz/`, `docs/architecture/` | Standalone single-file HTML Cytoscape.js visualizers generated by pipelines. C4 architecture-as-code models. |
| **5. Living Documentation & Governance** | `docs/decisions/`, `changes/unreleased/` | MADR 4.0 ADRs, towncrier fragment changelogs (zero merge conflicts), and executable doc-tests (`pytest-markdown-docs`). |
| **6. Lakehouse & Data Pipelines** | `src/pipeline/`, `config/params.yaml` | Dagster asset definitions, in-process DuckDB transforms, and centralized Pydantic-validated parameters. |

## Quickstart: Adopting This Template in Your Project

### 1. Copy the Structure
Copy the template files into your project root:
```bash
cp -r Universal-Agentic-Repository-Template/* /path/to/your-repo/
```

### 2. Configure Your System Invariants
Edit `AGENTS.md` with your repository-specific commands and rules (under 150 lines).

### 3. Generate Tool Adapters
Run the adapter generator to sync Cursor, Claude Code, and Antigravity:
```bash
python tools/agentsync.py
```

### 4. Enable Pre-Commit & Guard Hooks
```bash
pre-commit install
```
This activates `tools/guards/protect_paths.py`, which mechanically stops any AI assistant from deleting accepted ADRs or editing protected configuration files.

## The Developer & AI Collaboration Lifecycle

1. **Pick a Task:** Developer or agent runs `bd ready` to find unblocked work.
2. **Load Targeted Context:** Agent reads `AGENTS.md` and only the scoped rules matching the active files.
3. **Implement & Verify:** Make code edits. CI doc-tests verify code blocks in Markdown documentation.
4. **Wrap Up Cleanly:** Run `/wrapup` skill:
   - Emits a changelog fragment in `changes/unreleased/` (zero merge conflicts!).
   - Saves a session handoff note in `.agents/sessions/`.
   - Closes task in `.beads/issues.jsonl`.
5. **Human Merge:** Human reviews the PR. Pipeline materializes data and generates updated visual graphs.
